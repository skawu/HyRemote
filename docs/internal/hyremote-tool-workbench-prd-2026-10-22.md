## 1. 产品使命与边界

**产品定位（已选定）：D · 综合工作台。**

HyRemoteTool 是 HyRemote 官方的**Windows-first 本地桌面综合工作台**，统一承载：

1. **远程连接与操作（产品核心）**：连接用户明确给出的 HyRemote 业务应用访问端点，查看实时窗口/画面，明确选择只读或请求控制。
2. **诊断与支持**：区分客户端连接事实、本地 SDK 检查结果与用户导入的宿主诊断，生成可核实、可脱敏的工单证据。
3. **SDK 集成辅助**：让 Qt 开发者选择本地 SDK 安装目录与一种 C++/QML/Generic/QPA 接入方式，核对本机实际 artifact/兼容性，生成**经用户确认、可复制**的集成/启动步骤。
4. **未来安全主机管理扩展**：只有另行交付可信的 management API/认证/授权/安全传输后，才能呈现远端 Runtime 启停、策略与认证修改。不能把 RFB 错当管理协议。

**关键架构不变量：** HyRemoteTool 不是第二个 Runtime、不把用户业务应用嵌入进 Tool、不扫描端口/注入进程、不在用户未操作时选择设备/Qt Kit、不把采样 FPS 当作端到端延迟、不把主机是否允许输入猜测为已验证权限。RFB 访问面与未来管理面明确隔离。

历史 #378 的“宿主端控制面、不是 Viewer”已被 V0.3.0.0 的进程外 Viewer 实际实现与正式发布说明取代。旧 Issue 作为历史背景保留；本 RFC 描述新的 D 综合工作台边界。原 docs/internal/hyremote-tool-plan.md 仍是 **V0.3.0.0 已发布访问面事实**，并非完整未来 UX 的批准设计。

## 2. 目标用户与实际任务

| 用户 | 触发场景 | 成功定义 | 不应出现 |
| --- | --- | --- | --- |

| Qt 应用开发者 | 刚获得 HyRemote SDK，希望接入现有应用 | 能辨认实际 SDK 和 Qt Kit、选择四条对等路线、复制准确的最小步骤并获得自助故障解释 | 替用户挑 Qt 版本、盲目写工程文件、把所有平台宣称通过 |

## 3. 产品导航、内容密度与页面结构

采用 **Qt Widgets + QMainWindow / QStackedWidget + 任务型侧边导航**。窗口不是“连接表单 + 滚动日志”；远程画面是最大主内容区。

完整综合工作台的目标导航为：**连接**、**远程会话**、**诊断支持**、**SDK 集成**；右上角是设置、帮助、语言及软件信息。

**S1 首次交付时只呈现实际可用的「连接／远程会话／基础诊断」三个任务入口**。SDK 集成页将在 S3 实际交付后才出现在生产导航；不以带有“即将推出”按钮的空白页误导用户。首次启动默认「连接」，成功后进入「远程会话」。无会话时该页只展示可靠的连接引导，绝不显示虚假的会话状态。

### 3.1 连接页 — 未连接/故障恢复

~~~text
┌ HyRemoteTool ──────────────────────────────── 语言  设置  帮助 ┐
│ 连接 │ 远程会话 │ SDK 集成 │ 诊断支持                          │
├───────────────┬───────────────────────────────────────────────┤
│ 最近连接      │ 连接 HyRemote 应用                           │
│ 设备 A        │ [主机地址/域名_________________] [端口 5921]   │
│ 设备 B        │ [ 连接并只读查看 ]                            │
│ + 保存连接    │ 此会话默认只读；当前 RFB None 无加密          │
│               │                                               │
│               │ 没有连接时：操作说明/最近错误与修复建议      │
└───────────────┴───────────────────────────────────────────────┘
~~~

规则：
- 输入是 **host + port**，明确手动输入/选择已保存 profile；不进行 LAN 自动扫描、DNS 扫描、枚举远端进程或自动发起网络连接。
- 默认行为 **连接并只读查看**。保存 profile 必须明确点“保存”，不自动记存设备密码（当前也不支持）。
- 连接中显示状态与可取消操作；失败显示“哪里失败、可能原因、下一步检查什么”，同时保留输入的端点，提供“重试/复制错误/查看诊断”。
- 设备名称是**用户本地别名**，不是服务器宣称的强身份；最近连接仅保存非秘密信息。删除需作用域明确，不误删其他配置。
- 当前只支持一个活动远程会话；多个已保存端点不代表可同时发起多个 RFB 会话。并发会话需另行批准。

### 3.2 远程会话页 — 主工作区

~~~text
┌ HyRemoteTool ─ 设备 A / 192.168.1.25:5921 ─ 已连接 ──────────┐
│ 连接 │ 远程会话 │ SDK 集成 │ 诊断支持                         │
├───────────────────────────────────────────────────────────────┤
│ [只读 ●] [请求控制]  [适应窗口▾] [全屏] [重连] [断开] [详情] │
│                                                               │
│          ┌─────────────────────────────────────────┐          │
│          │                                         │          │
│          │         真实远程画面（主要空间）        │          │
│          │                                         │          │
│          └─────────────────────────────────────────┘          │
│                                                               │
│  安全：未加密 / 仅可信网络    FPS 28.4   1920×1080  详情 >   │
└───────────────────────────────────────────────────────────────┘
~~~

规则：
- 画面居中保持比例；模式：**适应窗口**、**100% 原始像素**（可滚动定位）、**全屏**。支持缩放/高 DPI 后的光标映射、滚轮和键盘焦点。全屏具备明显退出方式（Esc/F11，可见快捷提示），失联不隐藏退出控制。
- 默认只读。用户明确选择“请求控制”后，客户端才可发送鼠标/键盘事件。按钮名与状态应写 **“已开启本地控制发送”**，而非“宿主已授权控制”：现有协议没有独立权威信号证明远端执行了操作。退出会话/断线/窗口失焦应释放已按下的键/鼠标并回到只读/无发送状态。
- 不再以 RFB ServerName 是否包含 “view-only” 作为**安全权限证明**；可将其视作提示或兼容性线索，但“宿主输入权限”展示 **未知 / 未经验证**，除非未来有公开协议/Runtime 信号。
- 重连显式执行，不默认自动无限重试或自动恢复控制；保留端点，成功后仍默认只读。
- 底部只保留有用的少量数字，详细帧数/流量/握手/编码/错误进入按需抽屉。FPS 为客户端观察值，不声称物理交互延迟或主机 CPU 使用率。

### 3.3 SDK 集成页 — S3 才交付；引导而非替开发者做决定

~~~text
选择本地 SDK 安装目录 [浏览...]
安装树/manifest 检查：找到 / 缺失 / 未能证实二进制身份
Qt 环境：由用户明确指定 Qt Kit 路径 [选择...]
接入方式：[C++ API] [QML API] [Generic Plugin] [QPA]
当前资格：Qt6.8.3 Windows 已验证 / Qt5.15 限定 C++ Widgets 等
步骤：安装 -> find_package -> 链接/导入或启动参数 -> 部署 -> 运行 -> Viewer
[复制最小 CMake] [复制运行命令] [打开权威教程] [复制诊断]
~~~

规则：
- 读取**用户选定**的 SDK 路径，本地只读，验证 manifest/公开文件与 CMake 包的存在性；不得因为发现 manifest 就断言远端加载了这套二进制，也不自行运行用户程序。
- Qt Kit 必须遵循构建工具的显式选择契约：明确的 build.yml qt.prefix / CLI 优先，多 Kit 不自动挑最新，用户选择完整版本+编译器+架构。SDK 向导不复制一套自创的 Qt 发现逻辑。
- 四种接入方式对等，但显示 **按 Qt 版本、目标平台和组件限定的兼容状态**。当前 Tool 自身 CMake 项目链接 Qt6::，不能从 SDK Qt5 Widgets 成功推断 Tool 可用 Qt5 编译。
- 自动生成文本仅供复制；**不默默修改用户 CMakeLists、环境变量、registry、应用启动参数或项目文件**。未来可提供“预览差异 -> 用户确认 -> 写入”，需单独纳入交付。
- 对 QPA 必须显示特定 Qt private ABI 约束，不能仅按 Qt major 选中。

### 3.4 诊断支持页 — S1 基本诊断与 S2/S3 扩展分区

**S1 必须交付的基本诊断**只有客户端现场事实：当前端点、连接/握手阶段、可观察的 RFB 协议与安全模式、实际可测帧数/字节/尺寸/FPS、最后错误、有限长度活动记录、直接可操作的修复建议，以及用户触发的脱敏报告预览/复制/保存。未知字段明确为「未知／未观测」，不能输出主机 CPU、远程身份、端到端 P95 或远程授权已通过。

S1 之后才扩展其余两类带来源的卡片：
1. **S2 用户导入的宿主诊断**：用户主动导入由业务应用公开 diagnosticReport() 生成的快照；注明用户提供/时间/未独立验证。仅 Viewer 连接不推断远端 Runtime 状态。
2. **S3 本地 SDK 检查结果**：用户选定的本地安装树、manifest、版本、Qt Kit 与依赖检查；未执行显示「未检查」，manifest 只能证明声明内容而非已加载二进制。

操作：[复制脱敏摘要] [预览并保存报告] [打开帮助] [复制 Issue 模板]。错误与时间线须长度有界、无无穷大日志表。导出预览时默认隐藏凭证、密钥、鉴权应答；考虑对主机名/IP、路径提供可选遮蔽。不得默默上传任何会话数据。

### 3.5 设置/帮助/关于

只显示本产品已交付可运行的设置：界面语言、中英切换、视觉主题（跟随系统优先）、显示缩放、显式保存的本地连接配置、关于和文件位置。安全默认只读不可通过隐蔽自动化改变。未发货功能（远程管理、TLS、密码）不以禁用按钮/假选项诱导用户。

## 4. 关键状态机与交互契约

| 状态 | 主操作 | 输入策略 | 主区域/错误 |
| --- | --- | --- | --- |
| Idle / 无会话 | 输入端点、选择 profile、Connect | 禁止发送 | 连接引导与安全提示 |
| Connecting | Cancel | 禁止发送 | 连接进度、可取消 |
| Handshaking | Cancel | 禁止发送 | 协商信息；不显示“已连接成功” |
| Connected / ViewOnly | Request Control, Fit, Fullscreen, Reconnect, Disconnect | 不发送鼠标键盘 | 远程画面为主 |
| Connected / ControlRequested | Return ViewOnly, others | 仅客户端允许发送；宿主是否接受未知 | 清晰的本地控制请求状态 |
| ConnectionFailed | Retry, Edit, Copy diagnostic | 禁止发送 | 错误分类与可操作建议 |
| Disconnected | Reconnect, Edit | 禁止发送/释放按键 | 之前的画面不得误标为实时 |

**危险状态过渡：** 网络中断、窗口失焦、远端画面尺寸变化、视图缩放变化、关闭程序、切换设备，都要维护键盘/鼠标释放及视口坐标转换；后端状态是单一事实源，视图不应各自发明“已连接”状态。不会因加载已保存 profile 自动启动远程操作。

## 6. 技术模块与依赖方向

~~~text
                ┌────────────── HyRemoteTool（Windows Qt Widgets） ──────────────┐
                │  AppShell / Navigation / SessionWorkspace / SDK / Diagnostics │
                │                          ↓                                   │
                │  ConnectionController  SessionViewModel  DiagnosticPresenter  │
                │           ↓                  ↓               ↑                │
                │      RfbClient          FramebufferView    ReportBuilder      │
                │           ↓                                  ↑                │
                │       TCP / RFB                ProfileStore / SdkInspector     │
                └───────────┼──────────────────────────────────┼────────────────┘
                            │                                  │
                    已存在的访问面                       用户本地文件/显式导入
                            ↓
              业务 Qt Application + HyRemote Shared Runtime
                 （C++ / QML / Generic / QPA 对等接入）
                            ┊
                   [未来独立管理面；不在当前 RFB 中]
                            ┊
             Authenticated Management API + distinct listener
~~~

约束：
- **Qt Widgets 不是阻碍**；先建立明确的 view-model、状态控制、缩放组件、诊断模型和可自动测试的行为，避免继续扩大 469 行单文件窗口逻辑。
- **ConnectionController** 管连接命令、取消/重连、输入意图与状态；**RfbClient** 仍只做协议解析/帧输入；**FramebufferView** 只管呈现、交互映射及释放事件。
- **ProfileStore** 使用带 schema version 的本地非秘密数据，路径遵循操作系统应用配置目录，采用原子写入；便携包如需旁路数据目录，另有显式用户设置与可写目录检测，不擅自写仓库或 exe 安装目录。
- **SdkInspector** 只读指定目录、解析公开安装/manifest 合同；不能把公开包存在判为运行时身份 verified。
- **ReportBuilder** 将每项事实关联到来源和时间，明文展示 None/unencrypted 的限制；固定字段 schema、体积上限、截断标识、脱敏预览，不上传。
- 可预留 **ManagementAdapter** 作为接口边界，但当前无实例、无按钮、无端口、无虚假测试桩；管理能力先出独立协议、安全 Threat Model 和授权矩阵，再选是否合并进 UI。

### 6.1 当前真实安全契约

客户端当前只支持 RFB 3.8 / SecurityType None；没有 TLS/VeNCrypt 与 Tool 内 VNC Auth 口令入口。Host 的发布默认监听为 0.0.0.0:5921、未加密、远端输入默认关闭。**仅可信局域网或另外受到恰当保护的网络；不是 Internet 安全。** 将外网暴露、使用密码/证书与服务器策略变更视为专门安全产品事项，不能通过 UI 提示词解决。

### 6.2 将来的管理能力必须另立 RFC

管理面不能复用 RFB 数据端口；独立受认证授权的 API 和监听，仅在宿主显式启用时存在。默认 disabled、loopback；拓展到 LAN 要求明确绑定、认证、传输加密、访问控制、操作确认、错误/审计与拒绝权限测试。当前产品不许通过 Viewer 的输入模拟来声称“正式远程主机配置”。

### 7.2 S1 是完整用户成果，不是组件数量验收

必须以**最新版安装树中真实运行的 HyRemoteTool**验证以下闭环：

1. **启动/进入连接**：启动后无监听、无偷偷连接或输入发送；首页在 800×600 下能立即找到 Host、Port、只读 Connect；中文/English 均不需要翻过长表单；无设备时展示合理空态。
2. **设备连接管理**：用户输入地址或明确选本地保存档案，主动 Connect；保存/改名/编辑/删除及重启后的恢复准确。载入档案本身不主动连接、不自行选择其它端点。
3. **远程只读到显式控制**：连接/握手/已连接状态明确、画面真实更新；默认 RFB 客户端不发控制消息；明确点控制后才发送指针/键盘/滚轮，屏幕仅显示“客户端请求控制”，不能假称“主机授权”。切回只读、失焦、断线、关闭要释放 held input。
4. **画面操作**：在 800×600 和 1366×768 画面始终主导布局；Fit、原始像素 100% 可滚动、全屏（可 Esc/F11 退出）、DPI/缩放坐标、Host resize 与 Cursor shape 不导致错位。
5. **失败恢复**：无效地址、连接拒绝、超时、协议不兼容与远端断线能看到准确原因/下一步，明确重试/取消与断开后画面状态；不会静默无限重连，更不能自动开启控制。
6. **基本诊断**：只展示当前客户端真正测到的握手/模式、画面尺寸、FPS/吞吐、错误/事件；用户能主动预览并复制/保存长度有界、已脱敏的报告，UNKNOWN 不写成 PASS，无未经同意的上传。
7. **发布和回归边界**：\`--connect\`/\`--verify-ui\`/\`--test-seconds\` 与旧 Tool stdout 合同保持；fake-server/Qt offscreen UI/安装消费者测试、Windows Qt6.8.3 Ready PR CI PASS，独立审查无重大遗留。最后进行真实 Windows 图形/操作验收，记录**一个最终同 SHA**；非 Windows 测试缺失不阻塞。

**S1 排除项（不得偷加）**：SDK 检查器及接入模板生成、宿主 diagnosticReport() 导入、多设备同时远控、免安装便携承诺、浏览器 RFB、文件传输/剪贴板、认证/TLS 安全扩展、远端启停服务/改密码/监听策略。它们分别属于 S2、S3、未来单独立项或安全 RFC；**不构成 S1 未完成理由**。

### 7.3 S2/S3 的后置验收独立于 S1

- **S2 #587 进阶诊断**：用户自己导入宿主诊断；和客户端实时数据分开标“用户提供/未经独立核实”，大文件、错误格式、隐私字段 fail-safe；导出审查。**S1 的基本诊断已能独立使用，无需等 S2。**
- **S3 #588 SDK 集成**：用户指定本地 SDK、主动指定 Qt Kit（多 Kit 绝不静默选择）、选择 C++/QML/Generic/QPA，生成可复制命令并验证限定的 Qt5/Qt6/QPA 兼容性。不能推断远端运行身份；不能直接编辑用户项目。现场便携包由 #204 独立决定，不让它倒逼 S1 或 SDK 第一版。
- **S4**：先做管理 API 独立 RFC，后做代码；安全授权、监听和网络边界需显式批准，当前阶段不预先分配 Issue 给开发。

## 8. 验收矩阵与失败模式

- **导航/布局：** Qt UI offscreen 自动测试页面切换、禁用项、窄窗口、长 hostname、错误提示、缩放与语种；真实 Windows 上确认显示、可达性与全屏退出。
- **协议安全：** fake RFB 服务端覆盖 None、拒绝的安全类型、乱序/断线/截断、超大或非法矩形、重连复位；不会意外发送输入或记录秘密。
- **控制闭环：** 完成按下/释放/失焦/断线切换、跨缩放坐标映射测试；明确“本地请求控制 ≠ 宿主已授权”。
- **档案持久化：** profile 保存/改名/删、启动恢复、数据 schema 升级、损坏文件 fail-safe、无凭证存储；便携模式另验。
- **诊断来源：** 无 host report 时只显示客户端指标；导入文件的报告时间/来源与本地事实分列。Report 的 IP/路径脱敏由操作者预览并确认。
- **离线交付：** 在没有 Qt SDK、没有管理员权限且断网的 Windows 环境运行所交付包，核对许可证、清单、校验和与安全限制说明；未通过前不得叫“免安装保证”。
- **版本/发布：** S1/S2/S3 的具体 Feature 版本需由 #24/#95 对成果正式准入；不得把本设计当作已交付或 V0.3.3 直接发布通过的证据。

# HyRemote V0.3.3.0 release admission

## Purpose

This is the formal admission record for the V0.3.3.0 candidate. It is not a release note and does not itself authorize a tag. A row is admissible only when the implementation, automation, physical evidence and review disposition all refer to the same candidate SHA.

Current evidence baseline: `develop@3a65842` (2026-10-23). Candidate code SHA: **3a65842**; the same-SHA Windows L2 passed 83/83 after the WSL-stub test-registration fix.

## Admission rules

- The machine authority is `.github/release/release-trains.json`; V0.3.3.0 mandatory children are #144 and #175, with #261 as a candidate prerequisite.
- V0.3.3.0 requires **Windows x86_64 Qt 6.8.3** evidence. Linux desktop, ARM64/EGLFS and Wayland are **USER_VALIDATION_PENDING / NOT_RUN_NON_BLOCKING** per Owner #563, not release prerequisites; Qt portability does not mean those cells are Supported.
- Every **Windows mandatory** row must be `PASS` on the candidate SHA or carry an explicit Owner-accepted disposition. `PARTIAL`, `BLOCKED` or `NOT_RUN` on a mandatory Windows row are not release acceptance. A non-Windows `USER_VALIDATION_PENDING` row is **not required** and must never be represented as PASS.
- A hosted or synthetic run cannot replace real GUI/board/input evidence. A pass on an earlier SHA is not a pass on the candidate SHA.
- Review Gate must have zero unresolved P1/P2 threads, or a traceable `Review-Disposition:` for each.
- TLS, cloud relay, a complete management platform and hardware video encoding are outside this admission and cannot consume the V0.3.3.0 critical path.

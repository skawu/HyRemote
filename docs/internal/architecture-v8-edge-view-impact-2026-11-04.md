# 《HyRemote 产品架构文档》V8 变更范围与技术设计候选

> 关联 #827；输入基线 HYR-PD-001/V14、HYR-ARCH-001/V7 与《V15 增量正文设计候选》。V7 正式版及 G7 归档记录保持不变。本文件是 V8 受控设计内容与接口边界，不是已批准的新架构实现。

## 一、变更性质与技术判断

### 变化的唯一核心

在原来的三个产品组件（Framework/HyRemoteView/HyRemoteTool）及可选 Gateway 基础上，**同一个 HyRemoteView 产品新增工厂边缘接入角色**，在有权限的工厂 PC 上同时执行本地 Viewer 与受管 HMI 路由。异地 HyRemoteView 通过云端/自托管 Gateway 找到工厂站点，再向指定 HMI 建立最终受设备端验证的远程会话。

**不变：** Core 与 Shared Runtime、C++/QML/Generic/QPA 四种接入方式、Widgets/Quick、RFB 与 Native 的独立设备端协议、Direct 离线使用、设备端 View/ControlGrant 与隐私处理、本地业务优先、客户已交付权益。不能为了新的跨网络连接，在 HMI 上增添第二份 Runtime、在工厂 PC 上要求装另一个 Connector，或给每台 HMI 添加必须的公网监听。

### 与历史 #190 的关系

#190 中“出站接入、自托管 Gateway、最小路由授权、透明有界转发、审计不保留画面”继续作为设计参考；它过去**默认独立安装的 Edge Connector 与 Support Bridge**不再适用。原 Issue 仍保留历史记录，但实施方案须改为“HyRemoteView 内置边缘接入与远程客户端能力”。

## 二、建议的最小系统分层

```text
  异地办公 PC                             公网/客户自托管             工厂边缘 PC                          工厂业务网络
  ┌──────────────────┐                 ┌──────────────────┐       ┌──────────────────────────┐       ┌──────────────────────┐
  │ HyRemoteView     │                 │ HyRemote Gateway │       │ HyRemoteView             │       │ HMI 1 / HMI 2        │
  │ Remote Client    │──安全出站会话──►│ Control / Relay  │◄─主动──│ Local Viewer + Edge Role │──局域网──►│ Framework + Qt App   │
  │ 设备身份核验      │◄──透明加密传输──│ 会话协调/有界转发│──连接──►│ 指定设备路由/共享配置     │◄────────│ 设备端最终授权        │
  └──────────────────┘                 └──────────────────┘       └──────────────────────────┘       └──────────────────────┘
                                                                              │
                                                                              └── Direct 本地连接 HMI
```

框内的 Local Viewer / Edge Role 为**一个 HyRemoteView 产品及同一安装/升级责任**，并非要求安装两套应用。Gateway 为不同部署位置的可选服务。

数据面应避免双重图像处理：正常 HMI 画面由 Framework 采集编码一次，按端到端会话的许可经边缘端与 Gateway **字节透明路由**至异地 View。边缘端不构造第二个 HMI 截图/编码器。允许为了传输分帧、加密封包、限流进行必要的字节操作，但不做显示内容语义处理。

## 四、建议内部逻辑模块（均隶属同一 HyRemoteView）

- `LocalViewerWorkspace`：本地 Direct 及普通远程会话 GUI；保持设备焦点/授权状态。
- `EdgeSiteManager`：管理员显式启停、站点身份、共享 HMI 清单、可达性/有效期及状态；
- `EdgeConnector`（**代码模块名，不是独立安装软件**）：外向 Gateway 可信连接、心跳、重连、会话申请事件；
- `EdgeSessionRouter`：短时 Route Session、绑定 HMI 白名单与目标端点、双向有界字节转发、清理与撤销；
- `RemoteGatewayClient`：异地 View 的账号/站点选择与 Gateway 认证；
- `ManagedRemoteSession`：把受管网络路径和设备端 Native/RFB 访问抽象组合，但不将站点认证冒充设备授权；
- `EdgeDiagnostics`：可证明的站点连接、设备在线、申请、转发与失败状态，不记录画面或敏感输入。

这些是**架构职责划分候选**，不是要求建立七个独立进程/包/动态库。跨进程/同进程安排由平台安全隔离、自动运行要求和生命周期验证决定；任何选择都必须满足“只有 HyRemoteView 一个安装、统一升级/卸载”的约束。

## 五、三个安全边界（必须分别验证）

**边界 A：异地 View ↔ Gateway。** 操作者身份、租户/站点可见范围和一次性会话准入在此检查；云端设备在线不意味着获得任何 HMI 画面。

**边界 B：Gateway ↔ 工厂 View Edge。** 工厂端主动安全出站，认证明确的站点/边缘设备身份；只允许命中共享设备白名单的路由请求，且路由凭据绑定用户、站点、目标 HMI、协议类别与有效期限，不允许将路由资格当作跳板访问其他 TCP 服务。Gateway 不向 HMI 主动开入站公网端口。

**边界 C：异地 View ↔ HMI Framework。** 设备端独立核验最终设备身份、目标可见范围、ViewGrant/ControlGrant、受控隐私输出。传输层/控制面可由中继转发，但上游安全必须防止 Gateway 或 Edge 因拥有路由许可而自行获得新的 HMI 控制权。优先让 Native 的设备身份与内容保护端到端跨过两个中转节点；Managed RFB 是否允许以现有安全模式透传必须按安全实际证据限定，**不默认为公网可用**。

撤销链：任一站点共享被撤销→对应 Route Session 停止接纳并释放所有字节队列；设备端 Grant 被撤销→对应输入/画面输出强制停止。二者互相补充，不能由某一层单独替代全部安全规则。

## 六、运行/后台与可用性判断

客户端关闭一个画面窗口时，Edge 服务不应被偶然断开。**系统登录/注销/开机/升级后的可用性等级需要独立产品规格与平台验收**。建议：

1. 默认站点共享关闭，须客户管理员明确开启，能够随时停用，运行时有可见状态与审计。
2. 如要求无人值守跨注销持续连接，采用 HyRemoteView 同一安装包交付的受管后台机制；不能暗中要求用户安装“另一个 Edge Agent”。产品需以实际支持的 Windows/Linux 平台资格说明其启动模式、权限、日志和升级边界。
3. 边缘连通性使用“站点连接/共享设备可达/受管会话有效/设备授权”四个独立状态维度。任何一层失效时，不得沿用历史在线状态。
4. 网络恢复只恢复连接候选，不恢复过期的 HMI 控制许可，不重放未确认业务动作。

## 七、需要设计选择的技术点（先研究证据，不擅自冻结）

| 设计点 | 待比较选项 | 选择依据 |
| --- | --- | --- |
| View 内部运行隔离 | 单进程常驻 / 同安装包后台服务与 GUI 协作 | Windows 注销后的可用性、权限最小化、资源与升级可靠性 |
| 出站连接协议 | WSS/TLS TCP443 / HTTP2 CONNECT / QUIC 可选 | 工业防火墙实际可达、标准 TLS 身份、可观测性、运维成本 |
| 数据面封装 | Native 端到端加密字节透传 / 独立分段隧道 | 防中间节点读取、会话路由配对、容量限制 |
| HMI 端点定位 | 本地登记的设备身份→指定端口 / 静态注册清单 | 无扫描、无无限制网络代理，地址变化时可重新验证 |
| 边缘后台执行 | 用户登录期 / 管理员启用无人值守 | 不假在线、生命周期明确、部署“只装 View” |
| 多站点/高可用 | 单工厂边缘实例 / 多边缘主备 | 重复申请/重复输入防护、业务连续性、成本 |
| RFB 经受管路径 | 仅声明安全且可验证的兼容范围 | 传统 RFB 不提供完整用户认证及传输加密 |
| 性能预算 | 按工厂 PC 硬件等级与并发 Viewer/设备分别测定 | CPU、内存、吞吐、时延及 HMI 现场操作退化 |

**无须 Human 介入即可完成的工作：** 代码/协议技术路线调研、选项比较、威胁建模、验收方案、结构与样式规划。**必须 Human 参与的仅是**需要改变 G7 冻结边界的实质新方案、明显冲突的产品取舍和 V15/V8 正式批准。

## 八、验收结构

共用 V15 `EDGE-01`～`EDGE-12` 用户场景。架构层补充协议/资源用例：

- 建连：工厂 Edge 被动入站端口为零；可选 Gateway 由工厂 Edge 主动连接；站点身份变更必须重新核验。
- Route：白名单端点绑定、非法端口/跨站点/过期令牌/设备地址被替换都拒绝；不存在网段扫描及任意 TCP 代理。
- E2E：站点批准但 HMI 不批准不得查看；Viewer 已断线但云端未更新不得继续发送旧输入；撤权后的已排队数据失效。
- Resilience：Gateway/工厂 PC/HMI/Viewer 各自断线后，相关输入安全释放，其他 HMI 本地业务继续；Direct 不依赖云端。
- Performance：单一 HMI 不能因为异地一人连接就有两次画面采集/压缩；双向队列有上限，慢端不无限积压；CPU/内存/带宽和帧龄须有真实同条件记录。
- Compatibility：原 V14/V7 的 RFB Direct、Native 独立协议、Qt 四接入、OEM 离线权益不回退。
- Deployment：工厂端安装清单中只有 HyRemoteView；同安装包的可选内部运行机制不能以独立产品名或独立运维流程交付。

## 九、变更审查及状态

由于 V7 第 2、3、8、9、10、11、14、16 章存在新的强制职责/信任边界，**属于 G7 受控实质变更**，不能在旧 V7 正式版上直接覆盖；须形成 V15 送审稿、V8 送审稿和变更审批记录，批准后才让 V8 成为新的正式架构基线。

本设计稿不含 Native 1.0 wire 增删，不授权任何新 Gateway、云端身份、框架 API 或边缘服务代码立即开发。#190 历史实施结构须在本次变更批准后按新架构拆分实施里程碑，不得照旧先造独立 sidecar。

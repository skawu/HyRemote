# V15/V8 模块详细设计 03｜威胁模型、负向测试与产品验收矩阵

> #830；依据正式版 V15 第 8.6/8.7、10.1/10.2、11.4、13.8/13.9、14.1 和 V8 第 8.7、9.7、10.6、11.6、16.6。本文的 `EDGE-01..12` 是**工程测试追踪编号**：正式 V15 14.1 的新验收表实际包含 11 行新场景，其中“共享默认关闭与设备白名单”被拆成 EDGE-03/04 两个可独立证明的用例；不冒称 Word 原文有 12 行标号。

## 一、被保护资产及对手假设

### 被保护资产
1. HMI 的 Qt 业务状态、现场显示/物理输入、远程用户的当前 ViewGrant/ControlGrant/Scope。
2. 设备端允许输出的像素、敏感遮罩、键鼠/触控、文本和可能的未来文件/业务操作。
3. 工厂网络内 **未共享** 的设备与端口。
4. 站点/Edge/HMI 身份、操作者凭据、RoutePermit、密钥及设备可信材料。
5. Gateway 的租户隔离、审计事实、连接正确性、可用性和有界资源。
6. Direct 离线使用权益、其他 HMI 的合法会话与现场优先能力。

### 信任边界和攻击者
- **A 公网：** 恶意第三方可以监听/阻断/重放/发起受管网络请求；可能具有另一个合法租户账号。
- **B Gateway：** 云服务账号被窃、某业务组件错误配置、Relay 实例失陷或操作员越权。设计应使 Gateway 单独被攻陷**不自动获得 HMI 明文会话密钥或控制权限**；但可造成拒绝服务/元数据泄露，因此不能宣称完全不受影响。
- **C 工厂 Edge：** 工厂 View 进程/用户账号配置错误、恶意路由请求、端点 DNS 指向变更。若整台工厂 PC 已被攻陷，软件无法阻止攻击者绕过 HyRemoteView 直接访问本地 LAN；**“不支持任意代理”是产品自身强制策略，不是已入侵主机的硬隔离保证**。
- **D HMI：** 未经批准的 Viewer、错误或伪造设备、过期 Grant、远程用户利用控制动作影响生产。HMI 最终认证与授权在设备端执行。
- **E 本地客户端：** 窃取存储凭据、旧画面缓存、恢复旧会话后发送旧输入、托管账号失效时偷降级为明文 RFB。

## 二、主要攻击路径、设计控制与可执行反证

| 威胁 ID | 攻击方式/失败模式 | 必须的设计防护 | 最小负向验证 |
| --- | --- | --- | --- |
| SEC-01 | 未启用站点共享时 Gateway 列举 HMI | 默认关闭共享，Gateway 仅登记明确批准 DeviceId | 新安装后用户/站点搜索为空 |
| SEC-02 | 仅共享 HMI1，转发 HMI2/网段 192.168.x.x | Edge 强制 SiteId+DeviceId 白名单映射；不接受外部 Host:port | RouteOffer HMI2、任意 IP、非登记端口全部 DENY |
| SEC-03 | HMI1 地址变更成攻击者设备/DNS rebinding | 端点受本地登记、E2E HMI 证书/可信身份核验双约束 | 连接同 IP/域名的不同证书时 E2E_FAIL、无画面/输入 |
| SEC-04 | 攻击者重放 RoutePermit 或占用第三通道 | 一次性配对、token 绑定双方身份与 RouteId、原子消费 | 同一 token 第二次/第三通道配对 DENY |
| SEC-05 | 用租户 A 授权访问租户 B HMI | Gateway 租户作用域查询/Route + Edge Local ACL 再校验 | 交叉站点 DeviceId、wrong audience/edge/tenant DENY |
| SEC-06 | 过期 token、未同步撤销、管理员停用共享 | TTL、单调配置修订、Edge 本地优先撤销及主动 Route 取消 | 云断线时工厂管理员停用，现有 Route 终止，恢复不复活 |
| SEC-07 | Gateway/Relay 窃取 HMI 画面/键盘 | 异地 View ↔ HMI 的设备端身份与端到端加密；中间不终止 | 仅持 Gateway/Edge 凭据不能解密 HMI 内容，HMI 指纹伪造即失败 |
| SEC-08 | 将 Gateway 站点许可当 HMI ControlGrant | 独立设备端 View/Control/Scope 状态机 | Gateway 路由 PASS、HMI Grant DENY 时无画面或无法输入 |
| SEC-09 | 现场撤权时旧输入仍在网络队列 | HMI 收到撤权后拒绝旧 Grant 的**新输入**；撤销通道并释放 held state | 切换现场控制瞬间发送并发键鼠，旧 Grant 不能再执行 |
| SEC-10 | 隐私遮罩只在异地 Viewer 绘制 | HMI 按会话输出前过滤；中间无内容解释 | 已禁画面像素不能出现在 E2E 设备输出/缓存 |
| SEC-11 | 慢 Viewer 累积无界 Route 字节 | Edge/Gateway 每方向有界队列、背压和有界超时/关闭 | 受限速接收端下 RSS/队列不持续增长，其他 HMI 不阻塞 |
| SEC-12 | Edge 随意删 Native 密文或 RFB 增量帧 | 透明字节流只按序转发；**HMI 在编码加密前**决定合帧 | 分段/拥塞/重连中字节 hash、顺序及协议正确性一致 |
| SEC-13 | 网关断开后静默转 LAN 明文 RFB | 没有安全降级；Direct 是独立明确的用户动作 | 断开 Gateway 显示 Managed 失败，不自行打开未经保护 Direct |
| SEC-14 | TLS 证书错误后执行 ignoreSslErrors | 证书与主机身份验证失败即断；无隐式绕过 | 过期/域名不符/自签未知/被撤销证书全部 FAIL_CLOSED |
| SEC-15 | 因 TLS 1.3 早期数据重放授权/控制 | 非幂等控制消息不使用 0-RTT；应用层 nonce/幂等/单消费 | 两份相同 RouteRequest/Permit 不能生成两个有效设备会话 |
| SEC-16 | 退出/注销/重启后站点显示在线 | Edge lease/心跳与状态到期、UI 状态证明 | 杀 Edge/断电/注销后不再存在可连 Route；Gateway 状态过期 |
| SEC-17 | 断线后重放业务命令/旧控制权 | 新 Route、新 E2E 设备 Session、输入队列丢弃、业务结果待确认 | 断线前按住键/业务确认，重连不自动再次提交 |
| SEC-18 | 令牌/密钥出现在日志/配置/进程参数 | OS secret store、脱敏 structured logs、不持久化 route data | 导出日志、崩溃报告和设置中不可搜索到测试 secret |
| SEC-19 | 恶意客户端超大控制帧与非法 JSON 字段 | 明确消息大小/深度/枚举/状态机边界、分配前验证 | 64KiB+候选超限、重复字段、未知权限标志均被拒绝 |
| SEC-20 | 工厂 Edge 升级中断造成旧 ACL 与密钥错误恢复 | 原子配置迁移、回退和权限 fail-closed，单安装包 | 升级失败/回滚/恢复旧配置后不得恢复已撤销共享 |
| SEC-21 | 允许的 Gateway 用户借 Route 跳过设备身份验证 | E2E HMI 证书/设备 ID 与当前注册核对 | 假 HMI 带正确 DeviceId 但错误私钥时拒绝 |
| SEC-22 | 扩展功能字段污染 Native 1.0 wire | 受管控制独立命名空间、Native 协议版本不受新增字段影响 | Native/RFB 独立双协议兼容回归 |

**判定原则：** SEC-01~10、13~15、17~19、21、22 的确认绕过属于 P0 产品安全阻断；资源/安装/可用性问题需按严重性和业务结果评级，但绝不能发布为“已验证”而无实际证据。

## 四、证据等级与实际环境

| 层 | 允许证明的事实 | 必须同时写明的限制 |
| --- | --- | --- |
| T0 设计审查 | API/身份/状态/攻击路径已经定义并自洽 | 不能声明有可用软件 |
| T1 纯内存确定性协议/状态模拟 | 单用配对、ACL、超时、字节顺序、消息校验 | 不能证明 OS/TLS/真实网络正确性 |
| T2 可运行组件+本机网络 PoC | Gateway 与同包 Edge 的 TLS、断线、资源预算、密钥安全 | 不能证明公网代理/工厂部署 |
| T3 同一工厂两 HMI+双 View+Gateway | 真实产品业务旅程、授权、画面、输入、网络异常、权限 | 需要设备/各模块实际软件与验证记录 |
| T4 工业客户/生产参考环境 | 现场 CPU/内存/稳定性/设备多客户端、真实代理/运营配置 | 不自动涵盖其他 OS/SoC/Qt/大规模并发 |

所有测试报告必须包含 `SourceSHA`（各仓库与二进制）、设备版本与 Qt Kit、OS/CPU、网络条件、协议安全配置、是否实际 Viewer、用户操作过程、预期与实际、原始日志/数值、已知限制；没有就标 `NOT_RUN` 或 `NOT_QUALIFIED`。不把 0/1/2 Viewer 的 Windows 单机样本外推 RK3588 或复杂工厂局域网。

## 五、性能与资源验收设计（候选目标，非批准 SLO）

测试负载必须同时覆盖：0 Viewer / 1 Direct / 1 Managed / 同时 Direct+Managed / 2 HMI 多 Viewer；静态、多处局部变化 10Hz、源 60Hz 高频局部、源 30Hz 连续全屏变化；带宽正常/限流/间歇丢包及回连。观测：

- HMI 进程 CPU/内存与**实际有效画面采集**，是否因 Managed 路线发生第二次抓图/编码；
- 工厂 View 的 Edge CPU/内存、每条 Route 的队列峰值、连接数、Gateway 往返、吞吐/排队时间；
- 异地 Viewer 的有效不同帧 FPS、P95 帧龄、输入到可见反馈时延、本地工厂操作响应；
- 每次撤权/关闭的旧输入执行数量和授权旧缓存是否残留（安全门槛为 0）；
- 与同机 Direct 基线对照，明确因公网额外路径引入的开销，而不是比较不同设备的 CPU 百分比。

首次配额可依 01 的候选 `单 Route 每方向 256KiB、单 Edge 8 Routes、控制消息 64KiB、创建许可 60 秒` 做压力/恶意输入测试；**限额是候选，尚无目标硬件实证，不列为正式 SLO**。性能数据不能以长时未响应的自动 16 格测试作为唯一取得方式；每项短时独立运行、进度可观察，成本先评估，测试失败可以停止并保留已完成结果。

## 六、部署与安全验收的硬门禁

**禁止通过：**
- 用传统 RFB `Authenticated` / VNC Password 宣称数据已加密；
- 仅有 Gateway↔Edge TLS，而 View↔HMI 设备安全会话并未建立时宣称“已端到端”；
- 云端授予查看/控制后不再走 HMI 的当前 Grant 检查；
- 为完成工厂功能而让客户另装任意 agent、sidecar、独立 bridge；
- 将 Gateway Relay 变成任意 TCP 代理/内网扫描入口；
- 为减少 CPU，在中间 Relay 中剪掉加密 Native 字节或 RFB 增量数据；
- 只验证单机 loopback 就声明工业公网、安全、长期运行已达标。

**可进入下一阶段的条件：** Threat Model P0 有真实负向证据、关键依赖以精确 SHA 的真实 PoC 验证、软件安装与用户流程可重复。任何涉及已批准 V15/V8 实质取舍的重设才提交 Human，不能隐式消除原产品要求。

## 1. 发给本地 Owner 的立即执行指令

**当前开发 target = V0.3.4.0（Windows x86_64 / Qt 5.15.2 + Qt 6.8.3）**，不是 V0.4.0.0。现有任何以 V0.4.0.0 为“尚缺功能开发目标”的计划应转回 V0.3.4.0；保留 V0.4 未来测试/RC 准备，不开 `release/v0.4.0.0`，不改 `0.4.0.0` 的 `active:false`。

优先交付同一 Shared Runtime 对两代 Qt 主版本的真实产品化接入和 clean installed SDK；不复制 Qt5 Runtime，不把 Qt/Private API 引入 Core、Session 和 RFB 业务实现。新增/移除 Qt LTS 以后应主要修改 Kit Policy、有限 Qt shims、部署及资格矩阵。

**本任务书不是“所有技术项完成才知道版本号”**：本地负责人从现在开始就可以把 feature branch、PR、CI、测试报告、Issue 里程碑标为 **V0.3.4.0**，但不可在验收前创建发布 tag、宣称 Supported 或进入 V0.4 RC。

## 2. 本版本要交给用户的完整成果（而不是技术清单）

> 同一份 HyRemote API/SDK 在明确选择正确 Qt Kit 后，可以被已经存在的 **Windows Qt 5.15.2 或 Qt 6.8.3** 应用按经过认证的 UI/接入组合正确链接、安装、部署、运行、通过真实 RFB Viewer 查看/交互；每个未认证、不可适用或 ABI 不匹配的组合会明确提示，而非假阳性。

- **必须：** Windows x86_64，准确编译器工具链/arch/Qt patch，Kit 选择无歧义、错误 Kit fail-closed；Qt5 C++/Widgets 与 Qt6.8 已交付适用前端回归。2026-10-27 Owner D2 冻结 Qt5 bound：C++/Widgets 可在完整证据后 `SUPPORTED`；Qt5 Quick `EXPERIMENTAL / NOT_QUALIFIED` 且普通用户入口隐藏；Qt5 QML `UNSUPPORTED`、Qt5 Generic `UNSUPPORTED`、Qt5 QPA `REJECTED`。不得用 Qt5 Widgets CTest 覆盖未声明路线。
- **必须：** source `add_subdirectory()` 与 installed `find_package(HyRemote)`、`HyRemote::RemoteAccess` 和 `hyremote_deploy` 的正反例；Qt5 qmake legacy 用户有可运行的低侵入消费答案；QtPrivate 内部 ingress 和 QPA exact patch 私有 ABI 有明确边界、拒绝混用。
- **必须：** Qt 5.15.2 的实际承诺单元以及 Qt6.8.3 参考 baseline 在 **同一版本候选 SHA** 下构建/CTest/安装/真实 Windows 应用与 Viewer、键鼠释放/DPR/local Qt 响应、Raw/TRLE 和本机安全边界；RealVNC 7.15.1 是必需 maintained Viewer。D05 的 native popup 远程截图 `NOT_CONFIRMED` 依 Owner D1 转入 V0.4.0.0 资格工作，不单独阻塞 V0.3.4.0，且不得改写为 PASS。
- **必须：** `build.yml` 声明的合法 `build.directory` 必须全链路生效；Kit identity、candidate/sentinel、handoff、日志和测试路径跟随实际 build tree；不安全、越界、junction/symlink 或无法证明归属的目录 fail-closed，且不得放宽清理保护。
- **不承诺：** Qt6.5/Qt6.12（严格 V1 GA 后 #605）；Linux/Wayland/ARM64/EGLFS 的物理运行支持（用户验证，非 Windows 发布 blocker）；完整 Tool S1、主机路径+文字水印、Docker、TLS/云/Logo，以及任何 Qt5 Quick/QML/Generic/QPA 支持声明。
- **范围已裁决：** Qt5 非 Widgets 路线不再要求“先适配或获得新的产品范围决定”；Owner D2 已明确 UNSUPPORTED/REJECTED。`NOT_RUN` 仍不等于 `PASS`，真实证据仍必须与 exact candidate SHA 绑定。

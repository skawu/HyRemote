## Defect found by this acceptance run (fixed in #708)

The first RealVNC connection to `74fbd24` stayed on "Connecting…" while the server had already
closed the socket. Byte-level measurement on the same machine:

```text
accept                                  +239 ms
banner / version / security exchange    +252 ms
ClientInit from the viewer              +29178 ms
```

RealVNC asks the user to dismiss an **"Unencrypted Connection"** notice before it sends ClientInit.
The 3 s handshake bound aborted the socket long before that, so a first-time user could never
connect. #708 keeps the 3 s bound for the version/security exchange and gives the completed
security exchange a finite 30 s ClientInit window (and the same window for `AwaitInitialFrame`).

## Scope

This Feature makes remote interaction practical for ordinary LAN use without adding user configuration burden:

1. **RFB delivery efficiency**
   - practical damage and a maintained-viewer-compatible compressed path; profiling selected **Raw + TRLE**, and ZRLE is not required on current evidence;
   - incremental updates that show the newest useful state instead of replaying stale frames;
   - bounded queues/in-flight work, with local Qt responsiveness preserved;
   - truthful behavior when a viewer or transport cannot negotiate the preferred path.

2. **Performance baseline**
   - measure interactive latency, frame freshness, FPS, CPU, memory and queue bounds under #370;
   - record a V0.3.0.0 baseline and the V0.3.3.0 result;
   - no mandatory encoder/queue/bandwidth knobs for normal users.

3. **Maintained viewer interoperability**
   - validate the maintained standard-viewer paths (#175), not a private Viewer requirement;
   - record the exact viewer/version matrix used as evidence;
   - keep the access plane standard RFB; the companion Tool consumes the same improvements.

4. **Compatibility boundary**
   - **Windows x86_64 Qt 6.8.3** is the required validated/reference cell; Linux x86_64, ARM64/EGLFS and Wayland are user-validation pending and may be built/tested opportunistically;
   - this #144/#175 Feature and V0.4/V1.0 are never blocked by absent Linux/embedded runners, Viewer hosts or board/rootfs data (#563); neither does portability imply those cells are Supported;
   - four frontends remain peers; no new frontend or public API generation.

5. **Input and companion-tool usability (accepted add-on, 2026-10-20)**
   - make the remote cursor visible, with the server cursor pseudo-encoding and Tool rendering;
   - make the companion Tool bilingual, defaulting to Chinese;
   - let a remote click or key press request target activation without desktop-wide input injection;
   - release held remote keys and buttons when the Tool loses focus or input is disabled;
   - continue shape-aware cursor coverage for I-beam, resize, hand and custom cursors.

This item is deliberately bounded to the access experience. It does not add TLS, management-plane controls, a new frontend or user-facing encoder knobs.

- Qt 5.15/Qt 6.5 Windows compatibility remains governed by explicitly promised Windows cells under #57/#265. Linux/ARM64/EGLFS/Wayland validation is **nonblocking community/user work under #563** and no longer a mandatory pre-V0.4 baseline; #236/#154/#203 remain useful when user evidence or toolchains exist;
- optional management plane, remote start/stop access, policy/password changes, native TLS and future enhanced security are **not preallocated to any Feature**; conditional approval and #24/#95 activation are required. Existing shipped optional VNC password authentication remains a required accurate desktop interop test where applicable;
- new frontend, new protocol family, large public API/ABI change;
- private Viewer as a product requirement;
- tuning knobs exposed to ordinary users.

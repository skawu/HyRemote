# HyRemote v0.0.1.0 — Embedded C++ milestone release notes

Status: **candidate / acceptance pending**

`v0.0.1.0` is the Windows x86_64 + Linux x86_64 Embedded C++ product milestone. While the status marker above is present, this file is candidate material rather than a release claim. The milestone becomes a release fact only after #30 and its required SDK/build/view/input/reconnect/local-behavior evidence are accepted on both reference operating systems.

## Product scope

- one normal C++ application target: `HyRemote::RemoteAccess`;
- shared `HyRemoteRemoteAccess` runtime;
- `QWidget` and `QQuickWindow` application targets through the same facade;
- explicit `start()` / `stop()` lifecycle;
- loopback listener default and remote input disabled by default;
- standard RFB/VNC remote view and optional normalized remote input;
- disconnect/reconnect without rebuilding the target application;
- installed SDK and source `add_subdirectory()` consumption;
- one `hyremote_deploy(TARGET MyApp)` deployment entry point.

Normal use remains concise:

```cpp
HyRemote::RemoteAccess remote(&window);
remote.start();
```

Core, Session, capture/input adapters, transport and RFB implementation types are not normal application API.

## Security boundary

The V0.0.1.0 correctness transport uses **SecurityType None**. It is unauthenticated and unencrypted. Loopback and view-only are safe defaults for local/trusted use; direct public-Internet exposure is not a supported deployment profile.

## Acceptance boundary

While the candidate status marker is present, #30 acceptance is still outstanding. Required evidence includes both Windows and Linux reference matrices, clean SDK/source consumption, Widgets/Quick view and input, reconnect, deployment, and required local-input behavior. A GitHub Actions job that never receives a runner is not acceptance evidence.

After all #30 gates pass on `release/v0.0.1.0`, release finalization removes the candidate status line before the PR leaves Draft. The accepted branch then merges to `main`, receives annotated tag `v0.0.1.0` on the exact accepted main HEAD, and is reconciled through `backmerge/v0.0.1.0` to `develop`.

## 发布身份和范围

- 候选版本：`V0.3.0.0` / Product Preview（自助采用基础版本）；**这份文件是预发布说明，不代表 tag、制品或 GitHub Release 已经产生**。

- 候选参考环境：**Windows x86_64 / Linux x86_64，Qt 6.8.3**；Qt Widgets、Qt Quick/QML；QPA 仅声明精确 Qt/private ABI 和有资格的原生 delegate。

## 用户可以做什么

本版面向能够独立获取 HyRemote、完成 `build.cmd install`、查找安装 SDK、选定接入方式、在应用中启用和禁用远程访问、执行 `hyremote_deploy()`、在隔离安装树中运行和排错的普通 Qt 开发者。

四种**对等**接入技术使用同一个 Core 和 Shared Runtime：

- **C++**：公开 `HyRemote::RemoteAccess`，Widgets / Quick，显式生命周期；`hyremote_deploy(TARGET App)`。
- **QML**：`import HyRemote`，同一 Runtime；`hyremote_deploy(TARGET App QML)`。
- **Generic Plugin**：原生平台身份保持不变的 Qt-only 零代码激活；`hyremote_deploy(TARGET App GENERIC)`。
- **QPA**：精确 Qt 6.8.3 私有 ABI、经资格验证的 `qwindows` / `qxcb` 原生委托；`hyremote_deploy(TARGET App QPA)`。不可由此推断其他 Qt patch 或 delegate 合格。

四路线的最终支持声明以**同一冻结 SHA 的 Windows/Linux 干净安装/部署 L2 FULL_GATE** 为准；既往独立 PR 的 L1 结果不能拼成此项验收。

## 自助诊断和文档

同一个 Shared Runtime 的有界、无秘密 `diagnosticReport()` 和 Generic/QPA 事件日志可报告：版本/构建、Runtime 状态、配置/有效监听地址、访问/安全及远程输入、连接客户端数、最后错误，以及从应用可执行文件相邻 `HYREMOTE-MANIFEST.txt` 解析的**清单声明的候选部署身份**。这份清单必须与 `BUILD_IDENTITY` 对照；它本身**不能证明实际加载的 Runtime 或插件**来自同一候选。相邻清单缺失或无效时 `DEPLOYMENT_IDENTITY=unknown`，不能猜测来源。按任务组织的中英文入门、安装、四路线集成、Viewer 连接和故障排查指南与安装制品一同交付。

## 网络与安全边界

- 默认监听 `0.0.0.0:5921`（主机所有 IPv4 接口），**不是仅回环地址**；远程输入默认关闭。
- 默认认证：**关闭**；RFB `SecurityType None`。默认传输**未加密**。
- 构建并配置可选 transport-security 后可启用传统 RFB VNC 口令认证；这**不提供传输加密**。
- 请求未实现的 `AuthenticatedEncrypted` 必须在启动监听前失败关闭，不允许静默降级。
- 默认/未加密部署只能用于可信局域网，**不适合暴露到 Internet**。防火墙、监听地址和网络访问仍须由部署方管理。

## 已知限制和未完成资格验证

- 当前候选**不声明** Qt 5.15/6.5、ARM64、Wayland/EGLFS、其他 QPA ABI、任意 GPU/Quick3D 或任意第三方 Viewer 的普遍兼容性；这些属于 V0.3-family 到 V0.4 前的明确工作。
- RFB 有 Raw 回退与 TRLE/增量/Continuous/Fence 的代码与自动化回归，但**不以此宣称** V0.3.0.0 已满足维护版 Viewer 的实机全矩阵或物理局域网延迟 SLO。
- #410 真实用户交互延迟仍需维护版 Viewer/实际 LAN 测量并判定是否为本版本发布阻塞；不得将 hosted/offscreen 测量冒充真实 P50/P95。

## Release identity and scope

- Candidate: `V0.3.0.0` / Product Preview (self-service adoption foundation). **This is a pre-release note source, not evidence that a tag, artifacts or a GitHub Release already exist.**
- Release branch to create during qualification: `release/v0.3.0.0`; intended final tag: `v0.3.0.0`. The accepted commit, build identity, archives and checksums are release-time facts, not hard-coded into this source file.
- Lineage: the accepted `V0.2.0.0` First User Trial; `V0.2.0.1` was a maintenance repair to that lineage. This release does not claim the entire pre-GA V0.3-family platform/performance baseline.
- Candidate reference environment: **Windows x86_64 / Linux x86_64 with Qt 6.8.3**, Widgets and Qt Quick/QML. QPA support is scoped to exact Qt/private ABI and qualified native delegates.

## User outcome

A regular Qt developer should independently acquire HyRemote, execute `build.cmd install`, discover the installed SDK, select a route, enable/disable remote access, use `hyremote_deploy()`, run an isolated installed consumer and troubleshoot common failures.

Four **peer** integration technologies share one Core and Shared Runtime:

- **C++**: public `HyRemote::RemoteAccess`, Widgets/Quick, explicit lifecycle, `hyremote_deploy(TARGET App)`.
- **QML**: `import HyRemote` on the same Runtime, `hyremote_deploy(TARGET App QML)`.
- **Generic Plugin**: zero-code activation from an otherwise Qt-only application, preserving its native Qt platform, `hyremote_deploy(TARGET App GENERIC)`.
- **QPA**: exact Qt 6.8.3 private ABI with qualified `qwindows` / `qxcb` native delegation, `hyremote_deploy(TARGET App QPA)`. Other Qt patches/delegates are not automatically qualified.

The final four-route support claim requires **one frozen SHA Windows/Linux clean installed/deployed L2 FULL_GATE**; several historical PR L1 passes are not a substitute.

## Self-service documentation and diagnostics

The shared Runtime's bounded, secret-safe `diagnosticReport()` plus event-driven Generic/QPA output provides version/build identity, Runtime state, configured/effective listener, security/access and remote-input policy, connected clients, bounded last error and **candidate deployment identity parsed from `HYREMOTE-MANIFEST.txt` adjacent to the application executable**. Compare that declaration with `BUILD_IDENTITY`; an adjacent manifest **does not by itself prove which Runtime or plugins were actually loaded**. Missing/invalid adjacent manifest yields `DEPLOYMENT_IDENTITY=unknown`, not guessed provenance. Task-oriented Chinese/English guides cover installation, four-route integration, viewer connection, operations and troubleshooting against the same installed artifact.

## Security boundary

- Default listener is `0.0.0.0:5921` on all host IPv4 interfaces, **not loopback only**. Remote input is **off** by default.
- Authentication is **off** by default, RFB `SecurityType None`. Transport is **unencrypted** by default.
- Optional transport-security-enabled builds with valid configuration may provide legacy RFB VNC password authentication; that **does not encrypt the stream**.
- Unavailable `AuthenticatedEncrypted` must fail closed before opening the listener, with no silent downgrade.
- Unauthenticated/unencrypted deployments are limited to a trusted LAN and are **not Internet-safe**. The operator remains responsible for listener reachability and firewall policy.

## Known limitations and unqualified claims

- This candidate does **not** claim blanket qualification for Qt 5.15/6.5, ARM64, Wayland/EGLFS, unrelated QPA private ABIs, arbitrary graphics/Quick3D configurations or every third-party Viewer. These are explicit V0.3-family commitments before V0.4 entry.
- Raw fallback, TRLE, incremental delivery, Continuous Updates and Fence have implementation/regression evidence, but that is **not** proof of a maintained-viewer physical interoperability matrix or actual LAN interaction-latency SLO.
- #410 real-user interaction delay still requires measured maintained-viewer/direct-LAN evidence and a version-blocker disposition; hosted/offscreen P50/P95 must not be presented as the physical result.
- #405's original Linux xcb / OpenGL ES / Generic Quick / maintained-viewer path was closed by the Owner, but the visible record does **not include an original-path physical PASS**. No unsupported environment qualification is implied.
- Native TLS/VeNCrypt, Session Registry, cloud relay, first-party viewer and comprehensive vendor hardware acceleration are not this release's promises.

## Delivery, disable, update and rollback

Artifacts must derive from the accepted **exact tag**: source archives, Windows/Linux install-tree archives, the matching `SHA256SUMS` and final complete bilingual GitHub Release Notes. The installed/deployed tree carries `HYREMOTE-MANIFEST.txt` as a candidate identity declaration, to be compared with `BUILD_IDENTITY`; it is not standalone proof of loaded Runtime/plugin provenance. Consumers must not require build/source-tree paths or Qt SDK PATH repairs.

Application `stop()`, QML `enabled=false`, and documented Generic/QPA disable paths share Runtime lifecycle semantics. Roll back by reinstalling the entire last accepted product artifact, not by copying binaries from an old source checkout.

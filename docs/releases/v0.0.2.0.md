# HyRemote v0.0.2.0 — Declarative QML milestone release notes

Status: **candidate / acceptance pending**

`v0.0.2.0` is the Windows x86_64 + Linux x86_64 Declarative QML product milestone. It extends the accepted Embedded C++ runtime with a thin `import HyRemote` layer; it does not create a second Session, capture, input or transport implementation.

## Product scope

The intended declarative path is:

```qml
import HyRemote

RemoteAccess {
    target: mainWindow
    enabled: true
}
```

The wrapper uses the same shared `HyRemote::RemoteAccess` runtime as C++. Initial `enabled: true` is deferred until QML `componentComplete()` so property declaration order does not become user lifecycle glue.

The milestone also includes installed QML-module consumption and deployment through:

```cmake
hyremote_deploy(TARGET MyQmlApp QML)
```

The QML backing library is package payload, not a second consumer C++ target.

## Security boundary

QML preserves the common safe defaults and the same **SecurityType None** transport limitation: loopback by default, remote input off by default, no transport authentication or encryption claim.

## Acceptance boundary

This milestone remains pending until #31 accepts equivalent remote view/input/reconnect behavior on Windows and Linux against the accepted Quick/C++ runtime and the clean installed-QML deployment path. Unexecuted hosted jobs do not count as evidence.

The authorized release branch is `release/v0.0.2.0`; after acceptance it merges to `main`, receives annotated tag `v0.0.2.0` on the exact accepted main HEAD, and is reconciled back to `develop`.

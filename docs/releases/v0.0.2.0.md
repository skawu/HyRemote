# HyRemote v0.0.2.0 — Declarative QML milestone release notes

Status: **candidate / acceptance pending**

`v0.0.2.0` is the Windows x86_64 + Linux x86_64 Declarative QML product milestone. While the status marker above is present, this file is candidate material rather than a release claim. The milestone extends the accepted Embedded C++ runtime with a thin `import HyRemote` layer; it does not create a second Session, capture, input or transport implementation.

## Product scope

The declarative path is:

```qml
import HyRemote

RemoteAccess {
    target: mainWindow
    enabled: true
}
```

The wrapper uses the same shared `HyRemote::RemoteAccess` runtime as C++. Initial `enabled: true` is deferred until QML `componentComplete()` so property declaration order does not become user lifecycle glue.

The milestone also includes installed QML-module consumption and deployment through:

```cmake
hyremote_deploy(TARGET MyQmlApp QML)
```

The QML backing library is package payload, not a second consumer C++ target.

## Security boundary

QML preserves the common safe defaults and the same **SecurityType None** transport limitation: loopback by default, remote input off by default, no transport authentication or encryption claim.

## Acceptance boundary

While the candidate status marker is present, #31 acceptance is still outstanding. Required evidence includes equivalent remote view/input/reconnect behavior on Windows and Linux against the accepted Quick/C++ runtime and the clean installed-QML deployment path. Unexecuted hosted jobs do not count as evidence.

After all #31 gates pass on `release/v0.0.2.0`, release finalization removes the candidate status line before the PR leaves Draft. The accepted branch then merges to `main`, receives annotated tag `v0.0.2.0` on the exact accepted main HEAD, and is reconciled through `backmerge/v0.0.2.0` to `develop`.

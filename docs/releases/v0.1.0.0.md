# HyRemote v0.1.0.0 — Use It / Developer Preview release notes

Status: **candidate / acceptance pending**

`v0.1.0.0` is the **Use It / Developer Preview** release of the converged HyRemote product line: one Core, one shared
runtime and four peer application frontends, on the Windows x86_64 and Linux x86_64 Qt 6.8.3 reference. While the status
marker above is present this file is candidate material rather than a release claim: it becomes a release fact only
after the exact candidate has produced its accepted build, test, clean-consumer, example and product-fit evidence on
both reference operating systems.

- Release branch: `release/v0.1.0.0`

## What this release is for

A Qt developer can obtain a clean HyRemote SDK, choose the correct primary integration route from the minimal
developer entry, and make a normal Qt Widgets or Qt Quick application remotely viewable and controllable through a
small, truthful product surface - without adopting a second architecture, and without a security claim the build does
not actually provide.

## Primary paths

- **C++ API** — `HyRemote::RemoteAccess`, the single application-facing object, with an explicit `start()` / `stop()`
  lifecycle.
- **Generic Plugin** — an ordinary Qt application activated with `-plugin hyremote`: no HyRemote headers, no HyRemote
  API calls and no HyRemote link dependency in the application itself.

## Preview paths

- **QML API** (`import HyRemote`);
- **QPA** platform-plugin route.

Preview paths are exercised by the integrated regression and are *not* the surface this release's user promise rests
on. Their productization - the complete 01-09 learning flow, bilingual documentation and branding - belongs to a later
train and is not claimed here.

## Security boundary

- The listener is **loopback-only** in this Developer Preview; a non-loopback `Insecure` start is rejected before any
  listener is created.
- **Remote input is disabled by default** and must be enabled explicitly.
- `Insecure` is a **loopback-only** profile. It is unauthenticated and unencrypted.
- **VNC Authentication may be built** (`HYREMOTE_WITH_TRANSPORT_SECURITY=ON`). When available it authenticates the RFB
  stream with RFB VNC Authentication; **the stream is not encrypted**, and the capability depends on OpenSSL Crypto
  only.
- `AuthenticatedEncrypted` is **not available** in V0.1. It fails closed with `SecurityUnavailable` before any listener
  is created and does not fall back to a weaker profile.
- **This is not an Internet-facing remote-access server.** There is no "Internet-safe" claim, and an encrypted
  transport is not part of this release.

## Known limitations

- no TLS and no VeNCrypt transport - the real encrypted backend is V0.2 work (#143);
- no Session Registry or multi-session operations;
- **no Qt 5 qualification**: Qt 5.15 LTS, Embedded Linux, ARM64 and further QPA private-ABI combinations are outside
  this support statement;
- no ZRLE or damage-region encoding - the correctness baseline is RFB 3.8 Raw;
- QML API and QPA are **Preview** paths, not primary;
- remote input is limited to the normalized input model described in the input model document; composition/IME
  pre-edit is outside the V0.1 contract;
- complete bilingual documentation, full branding and the 01-09 learning curriculum belong to a later train.

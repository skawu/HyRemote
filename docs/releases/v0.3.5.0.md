## 本版用户成果

- **宿主配置与持久化路径**（#591）：显式配置、状态目录与 secret 引用选择在适用的 C++、QML、Generic、QPA 前端共用 Shared Runtime 的解析和诊断；Windows 原生 Unicode 环境路径得到保真处理，错误或不可用的选择拒绝启动，不会静默落到乱码目录。未交付数据库引擎或云控制面。
- **服务端静态文字水印**（#589）：调用方使用非空 UTF-8 文本启用；未启用时默认关闭；启用后默认为右下角单行、透明度 0.35，平铺须显式选择；水印仅作用于远程 framebuffer，不污染原应用本地显示；合成失败拒绝无水印出流。Raw/TRLE/增量区域与普通第三方 RFB Viewer 共用正确的远程画面。
- **明确的水印清除语义**（#777、PR #773）：Generic 可使用 `-plugin "hyremote:watermark-state=off"`；QPA 可使用 `-platform "hyremote:hyremote-watermark-state=off"` 清除已持久化的策略，随后不传水印选项的重启继续保持关闭。**仅传位置/透明度等修饰项而不传水印文本会被拒绝，不能隐式删除既有策略**。
- **Windows 启动参数与 QPA 修复**（#761、#774）：Windows Generic/QPA 零代码启动中的中文及空格水印文本可按原始码点保留；精确 Qt 6.8.3 QPA 显式 `delegate=windows` 得到正确解析，不会错误退回原生平台而失去远程服务。
- **持久化安全性**（#754）：有界读取和原子保存/清除水印策略；写入/清除失败拒绝远程服务并给出不泄露秘密的可观察错误。
- **工程测试效率**（#755、#756）：定向测试选择及治理修正属于开发者工具，不是新的远程访问功能，也不能替代完整候选测试。

## Product outcomes

- **Operable host paths (#591):** the shared Runtime resolves explicit configuration, writable state and secret-reference choices across applicable C++/QML/Generic/QPA frontends, with diagnostics and Windows-native Unicode environment-path correctness. Invalid choices fail closed rather than writing into mojibake paths. No database consumer or cloud-management surface is shipped.
- **Server-side static text watermark (#589):** nonempty UTF-8 text explicitly enables a watermark; off by default, a bottom-right single line at 0.35 opacity unless configured otherwise, and tiling only on request. Compositing affects the remote framebuffer, not local Qt pixels; the transport cannot silently substitute undecorated output if enabled watermarking fails. Works through normal Raw/TRLE/damage and maintained RFB viewers.
- **Explicit stored-policy OFF (#777 / PR #773):** Generic `-plugin "hyremote:watermark-state=off"` and QPA `-platform "hyremote:hyremote-watermark-state=off"` intentionally remove the stored policy; restart without watermark options remains off. Modifier-only options without watermark text are rejected with an actionable error and **must not silently clear an existing watermark**.
- **Windows Unicode argv + explicit QPA delegate (#761, #774):** CJK watermark text, including an embedded space, is preserved in Windows zero-code launch paths; `delegate=windows` is parsed completely in the exact Qt6.8.3 QPA cell, so an explicit delegation request cannot silently lose remote service.
- **Durable policy state (#754):** atomic, bounded policy storage with observable redacted errors and fail-closed writes/clears.
- **Build/governance improvements (#755/#756):** reliable focused test selection and Qt-free prose governance are maintainer improvements, not replacement evidence for the release gate.

## Security boundary

Security, compatibility and known limitations for this release:

- Default `0.0.0.0:5921` listener, remote input off. Default RFB `Insecure` offers neither authentication nor encryption; trusted LAN only, not Internet-safe. Legacy VNC authentication, where enabled/configured, does not encrypt traffic; `AuthenticatedEncrypted` fails closed.
- Windows Qt6.8.3 is the actually qualified four-route lane; Qt5.15.2 remains only its limited C++/Widgets cell, with no expansion of Qt5 Quick/QML/Generic/QPA to Supported. Linux, ARM64/RK3588, EGLFS and Wayland remain **user-validation pending**, not release blockers and not Supported.
- Host fonts determine available watermark glyphs; watermark is remote-frame only. No logo/image watermark, Docker joint deployment, TLS, Qt6.5/6.12 qualification, or V0.4 RC feature development is included.
- Field issues #565 and #567 are not represented as fixed or newly qualified without actual environment evidence.
- This is a **source-only** release plan. No binary installer, checksum or other release asset is claimed.
- The publication sequence remains protected review/merge to `main`, annotated tag at the resulting exact `main` HEAD, GitHub Release and post-tag/backmerge audit restoring `develop`'s `0.0.0` sentinel. This note never substitutes for verifying those individual actions.

## 用户可获得的能力与修复

- **共享 Runtime 与宿主路径**（#591、#793）：适用的 C++、QML、Generic、QPA 前端复用配置/状态/secret 路径选择和持久水印策略。改变描述符相对状态目录后，隐式恢复水印不会沿用上一目录的旧缓存；显式操作员策略保留优先级。
- **服务端文字水印**（#589、#754、#777、#784）：默认关闭，可显式启用文字、角落或平铺；只合成远端画面，写入持久策略按原子及有界规则执行；显式 OFF 和 QML `watermarkText: ""` 与省略属性有不同语义。Running 时被拒绝的修改不得污染生效配置；角落文字超出安全边界时拒绝远端输出，不回退无水印帧。
- **Windows Unicode/QPA**（#761、#774、#775）：中文、空格及配置/状态/secret 路径选择正确传递；在精确 Qt 6.8.3 私有 ABI 下 QPA `delegate=windows` 正常工作。
- **静态画面采集效率设计**（#789 / PR #797）：利用 RFB 已有的服务端像素变化反馈降低长时间静止 Viewer 的重复采集请求；画面变化或远程输入恢复活跃采集，保留有界背景探测。**本次未测量 CPU、FPS 或性能提升幅度**，不得将代码优化等同于 RK3588 实测改善。
- **断连后的帧缓存生命周期**（#790 / PR #798）：具备重新抓帧能力且已知尺寸的 Shared Runtime 在零 Viewer 时可释放原始帧缓存；独立 RFB Transport 保持既有即时首帧行为。RC6 实机验证了重连画面，没有测量 RSS/PSS；不宣称用户目标板高水位已解决。
- **开发者与传输验证**（#799、#800）：新增整屏 Raw/TRLE 单一 FramebufferUpdate 正确性与可选 1080p 诊断；修复先 `install` 再 `test` 时已安装 Qt DLL 污染测试插件搜索路径的问题，不再需要移动安装目录或覆盖 Qt 插件环境变量。

## 已知限制与公开反馈

- 用户现场 #789（RK3588 静态 CPU）、#790（断连内存高水位）、#567（条带刷新）仍需**项目自有目标硬件**验证用户侧改善。Windows 同机 RealVNC 通过、Raw/TRLE 诊断及静态采集优化均不等价于 RK3588 实测；不要求反馈用户承担研发测试。#791 双 EGLFS 实例的进程看护/DRM 独占冲突优先由宿主启动编排解决，未作为 SDK 已修复缺陷宣称。
- 旧的非阻塞诊断差异仍存在：某些 config 失败的 `LAST_ERROR_MESSAGE` 可能泛称 state，`HOST_PATHS_ERROR` 才明确指出 config；QML getter 的空请求值不一定反映隐式恢复后的生效策略。不能将其描述成安全绕过或已修复。
- 角标字形依赖宿主字体。#749 的合成器测量不包含抓帧、编码、网络、Viewer 绘制或完整资源开销，**不构成端到端性能承诺**。未实现 Logo/图片水印、Docker 或新的公网安全服务能力。

## Security boundary

- 默认监听 `0.0.0.0:5921`，远程输入默认关闭；默认 RFB `Insecure` **不提供身份认证或传输加密**，仅限可信局域网，**不可直接暴露公网**。传统 VNC Auth 不加密画面或输入。未实现的 `AuthenticatedEncrypted` 必须失败关闭，绝不自动降级。
- Windows x64、精确 Qt6.8.3 是本次四路线 Hosted 资格环境，QPA 仅精确私有 ABI 受限单元；Qt5.15.2 仅 C++/Widgets 受限单元。Linux、ARM64/RK3588、EGLFS、Wayland、Qt6.5/6.12、Qt5 QML/Generic/QPA 均不因本次 Windows 验收获得 Supported 状态。
- 本版只计划**源码 GitHub Release**，无经本轮签收的二进制安装包、签名或附件校验和。附注式标签只允许在受审的 `release → main` 合并后指向**精确 main 合并提交**；正式发布前不得声称标签、Release、backmerge 已完成。

## Product improvements

- **Shared Runtime host paths and watermark state (#591, #793):** applicable C++/QML/Generic/QPA integrations share explicit config/state/secret precedence. An implicitly restored watermark is reloaded when its resolved descriptor-relative store changes; an explicit operator choice keeps priority.
- **Remote-only watermark and fail-closed behavior (#589, #754, #777, #784):** off by default, opt-in text, corner/tile options and atomic bounded persistence. Explicit OFF differs from an omitted QML property; rejected Running-state edits do not replace the applied policy; corner text that cannot fit is rejected without leaking undecorated remote frames.
- **Windows Unicode and QPA (#761, #774, #775):** native Unicode paths/text and the Qt 6.8.3-specific QPA `delegate=windows` path work within their qualified cells.
- **Static capture scheduling (#789, PR #797):** RFB's existing served-pixel feedback drives bounded idle capture probing while new input/pixel changes restore active capture. **No RC6 CPU, FPS or percentage performance improvement was measured.**
- **Last-viewer frame lifetime (#790, PR #798):** producer-backed Shared Runtime may relinquish idle raw-frame storage when no Viewer remains; standalone RFB retains its original bootstrap contract. The physical RC6 reconnect was tested, but **RSS/PSS reduction on RK3588 was not measured**.
- **Transport/test reliability (#799, #800):** a full-frame Raw/TRLE wire regression and optional 1080p diagnostics; install-before-test no longer injects staged Qt DLLs into CTest runtime lookup, and no out-of-tree workaround or artificial Qt plugin-path override is required.

## Known limitations and user reports

- RK3588 user reports #789 (static CPU), #790 (memory high water) and #567 (visible stripe redraw) remain open for project-owned target-hardware outcome checks. A Windows 1080p wire test or same-host RealVNC pass does **not** prove the user's embedded issue is fixed. #791's EGLFS double-process DRM collision is a host-supervisor ownership concern, not a certified SDK remedy. Reporting customers are not required to run our engineering acceptance.
- Some invalid-config errors retain generic `LAST_ERROR_MESSAGE` state-path wording despite precise `HOST_PATHS_ERROR`; a QML getter may report the requested empty watermark rather than the implicitly restored applied one. These are disclosed as observations, not claimed fixes.
- Font availability affects watermarks; compositor-only performance numbers do not include frame capture, encode, network, Viewer painting or whole-process CPU/RSS. No image/logo watermark, Docker, or Internet-secure TLS RFB service is promised.

## Security boundary

- The default `0.0.0.0:5921` RFB `Insecure` listener offers **neither authentication nor transport encryption**; remote input is off by default. Use only on a trusted LAN, **never directly expose it to the public Internet**. Legacy VNC Auth does not encrypt session data. Unimplemented `AuthenticatedEncrypted` fails closed and must not downgrade.
- Qualified evidence is Windows x64 / Qt 6.8.3 four-route cells, with QPA constrained to the exact private ABI. Qt 5.15.2 covers bounded C++/Widgets cells only; Linux/ARM64/RK3588/EGLFS, Wayland, Qt 6.5/6.12 and unsupported Qt5 frontends do not become Supported.
- This is a **source-only** release plan. Do not claim binary installers, signatures, checksums, an existing annotated tag, a published Release or completed backmerge. After independent reviewed promotion to `main`, create an **annotated** tag on the resulting exact main HEAD, publish truthful bilingual source notes and audit the tag/backmerge.

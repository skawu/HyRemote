description: Owner 2026-11-12 纠偏：可选本地全量测试最多一次状态确认，随后立即提交 PR 交 CI；禁止循环轮询与重复全套
type: feedback

长任务收尾时，**一次**确认正在运行的本地完整套件真实状态（`build/test.log` 最终结论；若仍在跑则记录 `IN_PROGRESS_OR_TIMEOUT`、当前用例、PID、最后日志，不得写成 PASS），然后立即形成合法 `feature/<issue>-...` 分支、单一提交、PR，把验证交给既有 `ci-merge-verdict` / 受保护 lane。不得为等一个可选本地全量测试反复轮询、重启同一套件或重构/清理既有用户内容；定向负对照与已 PASS 的聚焦回归保留即可。

**Why:** 2026-11-12 #967 耗时 57 分钟，其中大量时间耗在重复完整 82 项套件与同一进度查询；云端 Owner 明确纠偏「不为了这一个可选本地全量测试无限推迟提交」，且 #970 的 `TEST_PLAN` 与 CI 规则才是准入，本地套件不是每次开发的必需门。

**How to apply:** 后续 HyRemote 长任务进入收尾阶段先查一次真实状态并如实记录；随后走 PR→CI→合并→最终 SHA 反证的路径，不再循环查进度。若源码被 Ninja 旧时间戳污染，只做受影响 target 的确定性重建、hash 匹配与聚焦测试，不整套重做。新增测试先按 #970 公布 `TEST_PLAN` 并说明既有 catalog 用例为何不足。

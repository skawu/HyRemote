---
name: 长命令静默时必须主动检查并回报进度
description: 交互/测试命令长时间无输出时先查进程与日志、给出用户可见进度，不得直接判定卡死或杀掉合法构建
type: feedback
---

任何步骤或命令长时间没有输出时，先主动检查其进程状态与日志，并向用户回报当前操作、实际阶段、已取得的证据与下一步；只有确认真正无进展时才按有界流程终止并重设计。**60 秒是本地工作的可见进度报告间隔，不是构建/测试的超时**；不得因为子进程静默就自动杀掉一个有效的 `build.cmd` 或 CTest 运行。

**Why:** 此前 slow-viewer 测试长时间静默且无人检查，浪费时间又没形成证据。但把「无输出」直接等同于卡死会与 root `AGENTS.md` 冲突——该文件明确规定 60 秒规则只约束工作汇报，不约束 CMake/CTest 的运行时长，并禁止对合法构建/测试加静默超时或杀进程。

**How to apply:** 长任务改成有界、可观测、持续给出进度更新的步骤；禁止无界 `Start-Sleep` 或后台静默等待。静默时先 `Get-Process`/读日志确认是否仍在推进，并按 AGENTS.md 的 60 秒可见性规则回报真实状态，不要用重复的空「仍在运行」伪装进度。CI 等待用 `gh pr checks --watch --interval 10` / `gh run watch`，完成即退出。只有确认进程真无进展或已失败，才终止、清理并如实标注 FAIL/BLOCKED。

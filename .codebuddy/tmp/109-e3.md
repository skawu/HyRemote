## E3: the declarative `stop -> change remoteInputEnabled -> restart` transition is observed on the candidate-line QML payload

**Payload**: `hyremote-qml-basic`, built from the candidate line (Ninja + `mingw1310_64` + Qt 6.8.3 `mingw_64`, Release, `-DHYREMOTE_BUILD_QML_API=ON`), launched as `-p 5966 --test-seconds 150 --policy-transition-ms 12000` through the payload's own documented helper (`examples/qml-basic/main.cpp:62-63`, QML side `policyTransitionTimer`).

**Instrument note first, because it nearly hid the evidence**: this payload emits its markers through QML `console.log`, which Qt writes to **stderr**, not stdout. Read from stdout the run looks like it produced nothing at all - the first look reported zero lines. The evidence below is that stderr stream, 12 lines, quoted verbatim.

| Phase | The application's own lines | Reading |
| --- | --- | --- |
| startup | `READY 5966` | the declarative runtime is up |
| session 1, default view-only | `CLIENT_COUNT 1`, then `CLIENT_COUNT 0`; **no** `APP_KEY` and **no** `APP_TEXT` | attempted remote input was not delivered while view-only, and the viewer really was connected |
| the declarative transition | `POLICY_STOPPED` -> `POLICY_INPUT true` -> `READY 5966` -> `POLICY_RESTART_REQUESTED` | the runtime was stopped, `remoteInputEnabled` changed while stopped, then restarted - the declarative form of the same stopped-runtime policy transition, in a single process |
| session 2, after the restart | `CLIENT_COUNT 1`, then `APP_KEY key=81` and `APP_TEXT text=q` | remote input reaches the QML application after the restart |

Two things stated plainly rather than smoothed over:

- **No pointer line appeared in this run.** The payload's click target is a specific QML item, and the generic pointer press used here (200,150) may simply have missed it, so **no pointer-delivery claim is made for E3** from this run. Key and text delivery are what the table claims.
- E3's "native local display/input before and during default view-only viewing" is **not** re-claimed here; this run covers the view-only non-delivery and the declarative transition.

**Still owed on E3**: the local native display/input baseline on this payload, the DPR interaction cell (needs a scaled or multi-display host), and Linux E3 (blocked on the Linux host).

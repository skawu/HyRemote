## E2: the same-process `stop -> configure -> start` policy transition is observed on the candidate-line Quick payload

**Payload**: `hyremote-quick-basic`, built from the candidate line (Ninja + `mingw1310_64` + Qt 6.8.3 `mingw_64`, Release), launched as `-p 5965 --test-seconds 150 --policy-transition-ms 12000` - using the payload's own documented acceptance helper, which exists on this line (`examples/quick-basic/main.cpp:102-104`).

Two viewer sessions with identical actions (key `q`, pointer press at 200,150), 14 s apart so the helper's transition falls between them.

| Phase | The application's own lines | Reading |
| --- | --- | --- |
| session 1, default view-only | `CLIENT_COUNT 1` (it really connected) then `CLIENT_COUNT 0`; **no** `APP_KEY`, **no** `APP_TEXT`, **no** `APP_POINTER` | view-only blocked remote input |
| transition | `POLICY_STOPPED` -> `POLICY_INPUT true` -> `POLICY_RESTART_REQUESTED` -> `READY 5965` | the same-process `stop -> configure -> start` transition with the application alive throughout - the process is not restarted |
| session 2, after the transition | `CLIENT_COUNT 1`, then `APP_KEY key=81 shift=0 ctrl=0 alt=0`, `APP_TEXT text=q`, `APP_POINTER button=1 x=200 y=150` | control mode delivers key, text and pointer; the Quick payload's focused text input received exactly one key and one text change |
| shutdown | `CLIENT_COUNT 0`, `STOPPED` | clean stop at the end of the bounded run |

Two notes:

- The delivered key line carries `shift=0 ctrl=0 alt=0`, which is relevant to the cross-cell held-input checklist. The held **balance across a transition** is still unobserved on the E1 payload (that payload has no key probe and adding one to the frozen candidate was declined).
- The transition happened only through the payload's own helper, and the viewer had to be reconnected afterwards - consistent with the recorded behaviour that a policy change stops and restarts the listener.
